# Establish board and thread reads from the returned page

For SDK 0.1.0, accept a board or thread read from structured fields alone when they establish the result. A direct read requires the returned page to establish the requested board or thread ID. An exact-post lookup must locate the requested post and report its exact URL and actual containing thread. If the caller requires a different thread, report the mismatch.

An empty structured board listing requires an explicit empty thread list and consistent evidence for the returned page and filter. A board can contain threads even when a particular filter matches none. A missing list or an unrecognized native listing is incomplete. An empty thread post list needs separate evidence that the view legitimately has zero posts. Every successful thread fixture at the upstream pin contains at least one post.

For an otherwise valid ordinary read, expose the viewer as a member for a positive viewer UID, a guest for an explicit zero, or unknown when identity cannot be established. Preserve each post’s visible content and any explicit restriction. A post can be readable even when its stored source is unavailable. An unexplained missing body makes the page incomplete. Preserve the forum’s row order and returned pagination, including repeated appearances of a promoted reply across pages. Callers can display established rows while the last page or continuation remains unknown.

Prefer complete structured fields. If they are unsupported or incomplete, assess the HTML already returned, including a legacy envelope’s document. An explicit login requirement, denial, missing resource, challenge or rate limit ends the read. If the outcome is still unresolved, make one additional native page request through the host with the same origin, intended session, target, page, filters and order. Assess it independently and report an incomplete read if it cannot establish an outcome. This bounds the cost of fallback while avoiding false empty results.
